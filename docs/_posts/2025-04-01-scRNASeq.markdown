# Motivation
  Virtually all animals adjust their behavior in response to changes in nutrient availability.

![Nutrient availability ~ behavior]({{ '/assets/images/nutrient_and_behavior.png' | relative_url }}){: style="width:auto; height:300px;" }

But that behavior is a whole-animal outcome of cellular responses. It would be simple-minded to assume all cells respond the same way. To really understand what's happening, we need a high-resolution view of how different cells react—and that's where **single-cell RNA-seq (scRNASeq)** comes in.

# Thought Process And Results
### What model organism to choose?
We need something whose behavior is **robustly regulated** by nutrient availability changes. The first thing that came into mind was the [dauer][dauer] stage of *C. elegans*, which is triggered when worms are short of food. **However**, dauer is triggered by some other cues as well, like high temperature and overcrowd population, which might very likely confound their response to purely "nutrient availability".

Is there a biological context that's ONLY and robustly triggered by nutrient availability? Turns out yes—the first larval stage (L1) of *C. elegans*. When worms hatch with food, they become an L1; when they hatch without food, they inevitably enter [L1 arrest][l1 arrest] where no development occurs and they focus on "survival".

### scRNASeq of fed and starved L1
As mentioned above, we sought to use scRNASeq. This would accomplish two things:

1) So far, no transcriptional atlas exists for the L1 stage of *C. elegans*—even though there are atlases for the embryo, L2, L4, and adult stages. So our study would establish the **first L1 transcriptional atlas**.

2) By doing differential expression (DE) analysis for individual cell types between fed (normal) and starved (arrested) L1, we would construct the **first starvation-response transcriptional atlas in any animal**.

Big shoutout to our awesome technician, who spared me from the joys of cell dissociation and library prep😉, so I could stay focused on the bioinformatics side.

### De-multiplexing NGS data of scRNASeq
We used the 10x Genomics' Gel bead-in-EMulsion (GEM) technology.

![GEM]({{ '/assets/images/tenx.png' | relative_url }}){: style="width:auto; height:300px;" }

Basically, this technology tries to make sure that no more than 1 cell is captured per GEM (so you would expect a lot of empty GEMs but very rare multiplet GEMs). The cell is lysed within the GEM and its cellular transcripts are released into the GEM. This technology tries to only capture mRNAs by using a poly-T sequence to recognize mRNA's poly-A tail (apparently this recognition isn't perfect, as we later found that it also recognized a lot of AT-rich non-mRNAs). All the recognizer sequence within the same GEM have the same barcode but each has a Unique Molecular Identifier (UMI). So ideally, because each GEM only contains zero or one cell, when it does contain a cell, **all mRNAs in this GEM coem from the same cell and have the same barcode, but each of them has a different UMI**. This is important, as it forms the basis of 1) how we distinguish transcripts from the same cell, and 2) how we count transcript abundance.

Instead of using 10x Genomics' CellRanger pipeline to align and count reads, we used the [scKB][sckb] pipeline, which adds customization functionality to the [kallisto bustools][kb] workflow that's designed to preprocess scRNASeq data. This is better than using CellRanger because we can now output **spliced AND unspliced** reads from the workflow. And it is always intriguing to be able to detect unspliced reads as they represent nascent transcripts, in contrast to mature, processed mRNA. And this, in turn, is important because the **transcript abundance is made up by active transcription - decay**. So an increase in transcript abundance doesn't necessarily mean it is transcribed more—it can simply be because the transcript is degraded less.

Okay! So to be able to get unspliced/intronic reads, we need to give scKB an intronic genome annotation file. And to do *that*, we need to index introns! Let's do it!

BSgenome.Celegans.WB.WS286 is a customized BSgenome; seed used to forge it can be found [here][bsgenome_seed]
{% highlight r %}
# load libs
library(BSgenome)
library(BSgenome.Celegans.WB.WS286)
library(BUSpaRse)

# intron-indexing needs a file telling it whether each chromosome is circular or not
cir_or_not <- setNames(c(rep(FALSE, 6), TRUE), c("I", "II", "III", "IV", "V", "X", "MtDNA"))

# extracts intronic sequences flanked by L-1 bases of exonic sequences (L equals 91 in the v3 generation of 10x scRNASeq technology)
get_velocity_files(X = "./ws286.gtf", L = 91, Genome = BSgenome.Celegans.WS286, out_path = "./", isoform_action = "collapse", chrs_only= TRUE, is_circular = cir_or_not, style="Ensembl")
{% endhighlight %}

Now we have some files generated in the output directory. Let's use them to index introns!

{% highlight bash %}
#!/bin/bash
# cDNA_introns_10xv3.idx is the name of the generated index file; cDNA_introns.fa was generated in the last step
kallisto index -i cDNA_introns_10xv3.idx cDNA_introns.fa
{% endhighlight %}

Now that we have the intronic info in hand, we'll start read-mapping!!

10xv3_whitelist.txt includes all valid barcodes in v3 generation of 10x Genomics scRNASeq technology and can be found [here][whitelist]
{% highlight bash %}
#!/bin/bash
scKB –file ./ -index ./cDNA_introns_10xv3.idx -dir_intermediate ./ -supported_tech 10xv3 -thread 16 -whitelist ./10xv3_whitelist.txt -dir_final ./
{% endhighlight %}

**Now we have our precious gene by cell matrix for all, spliced, AND unspliced read counts!!**

However, we can't keep all the cells in the matrix, as some of them are low-quality (e.g., **dying cells**). We need to censor some of them!

We can use a specific set of genes to **define low-quality**, and in our case, we chose mitochondrial genes, as it is known that when cells are dying, their mitochondrial content is released and mitochondrial gene proportion goes up in GEMs.

We used the [COPILOT][copilot] pipeline to iteratively classify cells into high- and low-quality groups until the result converges. below is an example code snippet.

Note: COPILOT censors cells dynamically. More specifically, here, it censors cells with a high mitochondrial transcript proportion, it removes multiplets using the [DoubletFinder][doublet] package, and it also censors cells based on a minimum UMI number for low- and high-quality cells and removes cells whose UMI count corresponds to the top 1% in all cells.
{% highlight r %}
# load libs
library(tidyverse)
library(magrittr)
library(COPILOT)

# get all mitochondrial genes into a vector
mt_genes <- read_tsv("ws286_mt_genes.txt", col_names = F) %>% .$X1

# dynamically censors cells
copilot(sample.name = "fed_starved_l1",
         species.name = "Caenorhabditis elegans",
         transcriptome.name = "ws286.gtf",
         mt.pattern = mt_genes,
         remove.doublet = TRUE,
         mt.threshold = 20,
         filtering.ratio = 1,
         top.percent = 1,
         min.UMI.low.quality = 10,
         min.UMI.high.quality = 25)
{% endhighlight %}

**OKAY!! What do we have now? We have gene by cell matrices for all, spliced, and unspliced reads in cells that passed the filter—"high-quality" cells! Cells we can trust! Let's move on to make better use of these matrices—let's Seurat them!**
